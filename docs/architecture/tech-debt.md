# 기술 부채 (Technical Debt)

> **목적**: 알려진 이슈와 개선이 필요한 항목을 추적합니다.

**마지막 업데이트**: 2026-02-15

---

## ⚠️ 현재 문제점 (High Priority)

### 1. 초기화 로직 분산 🔴

**문제**:
- `drive.service.js`, `storage.manager.js`, `auth.service.js`에 초기화 로직이 분산됨
- A를 수정하면 B, C가 파손되는 연쇄 부작용 발생
- 책임이 불명확하고 중복 작업 존재

**영향도**: 높음 - 새 기능 추가 시 항상 영향받음

**해결 계획**: 
- Phase 기반 플러그인 시스템으로 리팩토링
- 상세: [initialization.md](../features/initialization.md)

**우선순위**: P0 (최우선)

---

### 2. 중복 API 호출 🟡

**문제**:
- 루트 폴더(`Ghostwriter_Data`)를 여러 번 검색
- `drive.service.js`와 `storage.manager.js`가 각각 독립적으로 검색

**영향도**: 중간 - 성능 저하

**해결 계획**:
- Phase 시스템에서 context를 통해 결과 공유
- 한 번 찾은 폴더 ID를 재사용

**우선순위**: P1

---

### 3. 에러 핸들링 미흡 🟡

**문제**:
- 어느 단계에서 실패했는지 추적 어려움
- 전역 try-catch만 있고 단계별 에러 처리 없음

**영향도**: 중간 - 디버깅 어려움

**해결 계획**:
- Phase별 에러 핸들링
- 단계별 성공/실패 추적

**우선순위**: P1

---

## 🔒 보안 관련 (Medium Priority)

### 4. API 키 평문 저장 🟡

**문제**:
- `status.json`에 API 키가 평문으로 저장됨
- Drive 파일에 접근 가능한 사람은 누구나 볼 수 있음

**영향도**: 중간 - 보안 리스크

**해결 계획**:
- 브라우저 로컬 스토리지 사용 (단기)
- 암호화하여 Drive 저장 (장기)

**우선순위**: P2

---

## 🧪 테스트 (Low Priority)

### 5. 단위 테스트 부재 🟢

**문제**:
- 자동화된 테스트 없음
- 수동 테스트만 진행 중

**영향도**: 낮음 - 현재는 큰 문제 없지만 장기적으로 리스크

**해결 계획**:
- Jest 도입
- DriveService 모킹
- Phase별 독립 테스트

**우선순위**: P3

## 🚫 Will Not Fix (의도적으로 안 고칠 항목)

### 서버 없음

**이유**: 서버리스가 핵심 가치

서버를 추가하면:
- ✅ 더 많은 기능 가능
- ❌ 운영 비용 발생
- ❌ 사용자 데이터 소유권 상실
- ❌ 프로젝트의 정체성 상실

**결론**: 서버는 절대 추가하지 않음
